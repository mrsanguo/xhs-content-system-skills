# 视觉来源选择与确认门槛

## 原则

先确认视觉来源，再生成封面。通用搭建器不得把内置示例风格直接当成项目默认视觉，也不能只把文字放进色块就称为完成设计。

## 第一步：优先询问对标

定位和内容方向确认后，先请用户提供 1—3 个真正喜欢的账号、封面截图、图片或链接。用户已经提供时直接使用，不重复询问。

分析对标时区分：

- 可借鉴：明暗、留白、信息层级、字体气质、色彩关系、照片占比和栏目一致性；
- 不复制：账号名称、Logo、水印、人物、原文、独特图形和完全相同的构图。

把对标文件放进 `参考资料/视觉对标/`，把链接和分析结论写进 `视觉规范.md` 与 `project.yaml`。不要只保存一个链接而没有提炼规则。

## 第二步：没有对标时直接调用封面 Skill

如果用户没有对标，不要求用户先从几种模板中做选择。直接调用已配置的封面生成 Skill，让 Skill 根据标题、内容、平台和账号定位推荐或匹配视觉方向，再生成测试封面。

如果用户说“你定”，采用封面 Skill 推荐的首选方向；如果用户有明确偏好，把偏好写入本次生成要求。无论有没有对标，都要在生成后检查标题、比例、缩略图可读性和整体审美。

## 第三步：选择生成方式

项目必须在以下方式中明确选择一种：

### `external-skill`

调用已经安装的视觉 Skill 或设计工具。当前 `gzh-cover-generator` 同时支持小红书 3:4 封面、参考图编辑、纯文字排版和多风格生成，可作为优先选项；如果用户指定 Canva 或其他可用工具，记录实际选择。

把 Skill 名称写入 `visual_generation.generator_skill`。每日生产时必须读取并遵守该 Skill，生成后仍要检查标题准确、3:4比例、缩略图可读和项目视觉一致性。运行环境无法调用该 Skill 时停止出图，生成封面制作单等待处理，不得静默换成本地模板。

### `local-renderer`

只有用户明确要求固定模板和无人值守本地渲染时使用。根据对标或封面 Skill 已确认的成品，把颜色、字体、亮度、布局和安全边距固化进 `视觉模板/cover-theme.json`，再由项目本地渲染器重复生产。

通用模板附带的颜色与布局只是测试占位，不代表已确认视觉。不得仅把 `status` 改成 `confirmed` 就直接使用。

## 三版测试

使用同一标题和同一张真实素材制作三张有明显差异的 3:4 候选。外部 Skill 按其多风格或参考图流程生成；本地渲染器可临时使用 `photo-title`、`editorial-cards`、`brand-panel`，并加 `--allow-unconfirmed`。

逐张检查：标题逐字准确、比例正确、缩略图可读、主副标题断行、照片曝光、文字安全边距、颜色、字体、装饰密度和账号主页一致性。

## 固化结果

用户确认后同步写入 `视觉规范.md`、`project.yaml` 和 `视觉模板/cover-theme.json`：

- 对标来源与可借鉴规则；
- 生成方式 `external-skill` 或 `local-renderer`；
- 外部 Skill 名称或本地模板布局；
- 配色、字体、字号、断行和照片处理；
- 固定元素、可变元素和参考成品；
- 无法生成时的处理方式，默认 `stop`，不静默降级。

只有用户明确确认后，才能把 `visual_status` 和 `cover-theme.json.status` 改成 `confirmed`。
