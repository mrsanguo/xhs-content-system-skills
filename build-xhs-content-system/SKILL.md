# 小红书内容系统搭建器

## 目标

把任意行业的小红书项目从口头想法转成可交接、可审核、可每日生产的本地内容系统。先确认定位和视觉，再启用生产；不要用模板替代真实业务判断。

## 三层架构

1. 本 Skill 是项目搭建器，负责确认业务并建立项目系统；
2. `assets/project-template/skills/project-daily-producer/` 是通用生产模板，不写入行业案例、城市、产品或行动指令；
3. 初始化项目时，从通用模板生成 `skills/<项目标识>-xhs-daily-producer/`，以后只运行这个项目专属 Skill。

用户只需启动项目搭建器。通用模板是内部母版，项目专属 Skill 是搭建结果，不要求用户手工依次调用三层。

## 模式判断

- 用户尚无完整项目：执行“新建模式”。
- 用户已有账号或文件夹：执行“接管模式”，先审计再补齐，禁止覆盖原文件。
- 用户要求今天或明天内容：执行“每日生产模式”。
- 用户提供发布数据、评论或私信：执行“复盘模式”。

## 新建模式

1. 读取 [references/onboarding-and-positioning.md](references/onboarding-and-positioning.md)，每轮只问 3—5 个关键问题。
2. 信息足够后输出三个定位候选，说明受众、信任理由、内容入口、产品和风险；等待用户确认定位。
3. 读取 [references/content-system.md](references/content-system.md)，生成账号包装、3—5 个栏目、30 个基础选题和前 14 天计划。
4. 读取 [references/visual-approval.md](references/visual-approval.md)，优先请用户提供 1—3 个视觉对标；没有对标时直接调用已配置的封面生成 Skill。用户确认生成结果和生成方式后，再固化视觉规范。
5. 为项目确定一个小写英文 Skill 名称，推荐 `<项目标识>-xhs-daily-producer`，只使用小写字母、数字和连字符。
6. 使用 `scripts/init_project.py --daily-skill-name <名称>` 建立固定项目目录。已存在的非空目录必须停止，不覆盖。
7. 初始化脚本从通用生产模板生成项目专属 Skill，并把每日生产、封面渲染和校验脚本复制进去，保证项目文件夹可以独立交接。
8. 将确认信息写入 `project.yaml` 和对应 Markdown 文件；未确认内容标记“待确认”。没有对标时，记录封面 Skill 推荐的视觉方向，不强制创建额外的人工风格选项。
9. 生成第一条完整图文或视频内容包，并用项目专属 Skill 内的脚本完成素材索引、封面渲染和校验。
10. 用户确认首条内容和视觉后，再准备每日自动运行；未经许可不得加载系统定时任务。

## 接管模式

1. 读取目标目录内的 `AGENTS.md`、`README.md`、`project.yaml`、当前进度和最近输出。
2. 运行 `scripts/validate_project.py --project-root <目录>`，列出缺失项和冲突。
3. 保留现有素材、成品和用户改动，只补充缺失文件；需要调整定位或结构时先给差异清单。
4. 将旧素材统一登记到根目录素材库，不复制进新的日期目录。

## 每日生产模式

1. 读取项目根目录 `AGENTS.md`、`project.yaml`、定位、内容、视觉、当前进度及最近 14 天输出。
2. 从 `project.yaml` 的 `daily_producer.skill_path` 找到项目专属 Skill；不存在时停止，不临时使用其他项目的生产 Skill。
3. 运行项目专属 Skill 内的 `build_material_index.py` 更新素材索引。
4. 根据 14 天计划、最新真实反馈和去重结果选择一条内容；不得杜撰经历、数据、用户反馈或效果。
5. 运行项目专属 Skill 内的 `create_daily_package.py` 创建空内容包；日期目录非空时停止。
6. 图文：生成标题、正文、封面配置、封面成品、素材引用和发布记录。视频：生成口播稿、镜头清单、字幕重点、发布配文及补拍要求，不伪造真人视频。
7. 从 `project.yaml` 的 `visual_generation` 读取封面方式：`external-skill` 时调用并遵守指定视觉 Skill；`local-renderer` 时使用已确认的 `视觉规范.md`、`视觉模板/cover-theme.json` 和项目本地渲染脚本。方式或视觉未确认时停止出图，不自行选择默认风格。
8. 运行项目专属 Skill 内的 `validate_daily_output.py`；通过后状态仍为“待审核”，不得写成“已发布”。

无人值守入口使用：

```bash
scripts/run_daily.sh --project-root /absolute/project/path --date YYYY-MM-DD
```

只检查运行条件时增加 `--dry-run`。

## 复盘模式

读取 [references/review-loop.md](references/review-loop.md)。区分事实、推断和建议。数据不足时不改定位；需要调整定位、产品、价格或视觉时先获得用户确认。

## 文件与事实优先级

1. 当前对话中用户最新明确指令；
2. 项目 `project.yaml`；
3. 项目 `AGENTS.md`；
4. 定位、内容与视觉方案；
5. `当前进度.md`；
6. 历史输出和复盘数据。

发现冲突时停止自动改写，在当天记录中列出冲突和建议。

## 安全边界

- 不自动发布小红书，不登录平台，不发送真实私信或评论。
- 不覆盖已有日期目录、历史成品和原始素材。
- 不把图片、视频复制到日期目录，只记录根目录相对路径。
- 不公开未经确认的地址、价格、联系方式和个人隐私。
- 不承诺流量、成交、收入或变现结果。
- 不把某个行业案例硬编码到通用 Skill。
- 项目模板和 Skill 内不得写入本机用户绝对路径、密钥、令牌或私有素材。

## 完成标准

- 定位、目标用户、产品和转化路径已确认或明确标记待确认；
- 固定目录、`project.yaml`、AGENTS 和交接文档齐全；
- 14 天内容计划和第一条完整内容包已生成；
- 视觉对标（如有）或封面 Skill 推荐方向、生成方式和参考成品已经用户确认并保存为可复用规范；
- 每日生产不会覆盖历史，也不会复制根目录素材；
- 项目专属每日生产 Skill 已生成，名称与路径写入 `project.yaml`；
- 项目和每日输出校验通过；
- 其他智能体只读取项目文件夹即可继续工作。

详细目录和每日文件要求见 [references/output-contract.md](references/output-contract.md)。
