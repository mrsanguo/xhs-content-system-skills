# 小红书内容系统 Skill 使用指南

## 一、你最后会得到什么

运行项目搭建器以后，会得到一个可以长期交接的项目文件夹。定位、账号包装、内容方案、视觉规范、素材库、每日输出、复盘数据和项目专属 Skill 都放在里面。

以后换一个 Codex 任务，或者把整个项目文件夹交给其他智能工具，它可以先读 `AGENTS.md`、`project.yaml` 和当前进度，再继续生产，不需要重新听你讲一遍项目背景。

## 二、先理解三层结构

### 第一层 项目搭建器

`build-xhs-content-system` 负责把模糊想法变成完整项目。它会询问业务、用户、产品、案例、内容边界和视觉参考，随后生成项目文件。

### 第二层 通用生产母版

母版放在项目搭建器内部。它只规定每日内容应该怎样读取方案、选择素材、归档文件和校验结果，不包含任何具体行业信息。

这层不需要单独安装，也不需要用户直接调用。

### 第三层 项目专属每日生产 Skill

新项目建立时，搭建器会从母版生成一个专属 Skill。它只读取当前项目的定位、素材和历史输出。

一个账号对应一个项目文件夹，也对应一个项目专属每日生产 Skill。不要拿甲项目的每日 Skill 去生产乙项目内容。

## 三、安装

### 方法一 从 GitHub 安装到 Codex

```bash
python3 ~/.codex/skills/.system/skill-installer/scripts/install-skill-from-github.py \
  --repo mrsanguo/xhs-content-system-skills \
  --path build-xhs-content-system
```

看到安装成功以后，新建一个 Codex 任务再调用。

### 方法二 手动复制

1. 下载本仓库。
2. 找到 `build-xhs-content-system` 文件夹。
3. 把整个文件夹放进当前智能工具的 Skills 目录。
4. 重启工具或新建任务。
5. 检查可用 Skills 中是否出现“小红书内容系统搭建器”。

其他智能工具没有 Skills 机制时，把整个项目文件夹交给它，并让它先完整读取根目录 `AGENTS.md` 和 `project.yaml`。

## 四、从 0 到 1 新建项目

第一次可以直接输入。

```text
使用 $build-xhs-content-system，帮我搭建一个新的小红书内容项目。
行业是宠物营养咨询，项目目录由我提供。
先梳理定位、产品和内容方向，再确认视觉，不要直接套默认封面。
```

系统会分几轮询问关键信息。至少要说清下面这些内容。

- 你做什么业务。
- 你最想服务哪类人。
- 对方现在遇到什么具体问题。
- 你准备通过什么产品或服务变现。
- 你有哪些真实经验、案例和素材。
- 哪些信息不能公开。
- 你喜欢或想参考哪些账号、截图和封面。

定位和视觉没有确认时，系统可以保存草稿，但不会把测试占位封面当成正式视觉。

## 五、接管已有项目

已有账号和文件夹时，可以输入。

```text
使用 $build-xhs-content-system 接管这个小红书项目。
先读取现有文件并列出缺失项，不覆盖已有素材和成品。
```

系统会先检查 `AGENTS.md`、`project.yaml`、当前进度和最近输出。已有规则与新要求发生冲突时，它应该先说明冲突，不直接改写。

## 六、每天生产内容

项目建好以后，优先调用项目文件夹里的专属每日生产 Skill。

```text
使用当前项目的每日生产 Skill，生成明天的一条小红书待审核内容。
```

图文内容通常包含。

- 当天选题。
- 二十字以内的发布标题。
- 正文与话题。
- 封面配置和封面 PNG。
- 根目录素材引用记录。
- 发布记录。
- 自动生产记录。

视频内容通常包含口播稿、镜头清单、字幕重点、发布配文和补拍要求。系统不会伪造真人视频。

## 七、按日期归档

项目根目录统一保存原始素材。

```text
项目根目录/
├── 图片素材/
├── 视频素材/
├── 参考资料/
├── 视觉模板/
├── 数据复盘/
├── skills/
└── 输出/
    └── YYYY-MM-DD/
        ├── 当天选题.md
        └── 成品/
```

日期目录只记录调用了哪些根目录素材，不再复制图片和视频。这样不会越做越乱，也能保留原始素材的唯一来源。

## 八、封面怎样处理

封面要先过视觉确认门槛。

1. 优先提供一至三个对标账号、截图或封面。
2. 系统提炼可借鉴的配色、排版、照片使用和信息层级。
3. 不复制对方的品牌、Logo、原文和独特图形。
4. 用户没有对标时，直接让封面 Skill 根据标题、内容和账号定位设计生成。
5. 只有用户明确要求固定模板时，才固化成本地模板。

如果选择外部视觉 Skill，需要在项目配置中记录实际 Skill 名称。如果选择本地模板，需要先确认测试样张，再把占位标记关闭。

## 九、复盘

有发布数据、评论和私信以后，可以输入。

```text
使用 $build-xhs-content-system 复盘最近七天的小红书内容。
把确定的数据、合理推断和下一步建议分开写，不要因为三条内容就直接改定位。
```

数据少时，先看内容方向有没有连续、进来的咨询是否符合目标人群、标题与封面有没有完成筛选。涉及定位、产品、价格和视觉的大改，要先由用户确认。

## 十、自动运行与边界

项目专属 Skill 带有脚本入口，可以为指定日期建立内容包和校验结果。自动运行只负责准备待审核内容。

它不会做下面这些事。

- 登录或操作小红书。
- 自动发布内容。
- 自动回复真实评论和私信。
- 覆盖已经存在的日期目录。
- 修改原始图片和视频。
- 编造案例、收入和用户反馈。

建议先手工运行并审核几次。等定位、文案和视觉稳定以后，再考虑系统定时任务。

## 十一、常见问题

### 为什么安装一个 Skill，项目里又多了一个 Skill

项目搭建器是通用能力。新生成的每日 Skill 是项目实例，只服务当前账号。这样才能让多个项目互不污染。

### 能不能给其他行业用

可以。通用 Skill 没有写死 OPC、城市、工位和行动指令。每个新项目都要重新完成业务定位和视觉确认。

### 能不能直接自动发布

当前版本不支持。内容统一标记为待审核，公开发布保留给用户。

### 为什么封面没有直接生成

视觉参考、生成方式或测试样张还没有确认。系统会停在这里，避免默认模板被误当成正式设计。

### 图片素材要不要复制进每天的日期文件夹

不用。原始素材只放在根目录素材库，每日内容记录相对路径和用途。
